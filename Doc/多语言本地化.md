# NewLife.IoT 多语言本地化

> 基线：NewLife.Core v12 运行时本地化｜词表：31 种语言｜源文：英文

本文档说明 NewLife.IoT 四个包（`NewLife.IoT`、`NewLife.IoTSerial`、`NewLife.IoTSocket`、`NewLife.IoTDatabase`）如何接入 NewLife.Core 的运行时本地化能力。

## 1. 设计取舍

| 项 | 选择 | 理由 |
|---|---|---|
| 词表键 | **英文原文** | 未提供译文的语言自动回退英文，接入成本为零；键即文案，不存在"键名与文案两层维护" |
| 译文载体 | 仓库根目录 `Locales/*.yml` | 编译期由 NewLife.Core 源生成器打包为 Deflate 压缩词表，不依赖 ResourceManager 与卫星程序集，NativeAOT 下可用 |
| 语言集 | 31 种：`ar`、`bn`、`cs`、`da`、`de`、`el`、`es`、`fa`、`fi`、`fr`、`he`、`hi`、`hu`、`id`、`it`、`ja`、`ko`、`ms`、`nb`、`nl`、`pl`、`pt`、`ro`、`ru`、`sv`、`th`、`tr`、`uk`、`vi`、`zh-Hans`、`zh-Hant`（英文为源文与兜底，不单独建表） | 与 NewLife.Core 词表集对齐；`zh-Hans`/`zh-Hant` 统一承接 `zh-CN`/`zh-TW` 等区域性 |
| 词表共享 | 四个包共用同一份 `Locales` | 四个包同仓发布、消息高度复用；注册为进程级全局表，任一包加载即可查表 |
| 翻译入口 | 异常 `L.T(...)`；日志直接写英文模板 | `Logger.Format` 自动翻译日志模板；`IoTException` 与结果类型的 `Fail` 方法内部翻译 |
| 类型显示名 | `TypeHelper.GetIoTTypes` 每次调用按当前语言翻译 | 不在静态字段缓存译名，避免进程内切换语言后仍返回旧语言 |
| 运行时元数据 | `[LocalizedDisplayName]` / `[LocalizedDescription]` 以英文键标注 | 继承 BCL 特性并重写取值属性，`GetDisplayName`/`GetDescription` 与 Xml 注释生成逻辑无需改动即可获得当前语言译文 |
| 程序集元数据 | `AssemblyTitle`/`Description` 用英文源文，同一字符串入词表；中英双语描述放 `PackageDescription` | 程序集与 NuGet 元数据是单值，不随界面语言切换；展示层翻译，NuGet 列表描述不受影响 |
| 区域性敏感逻辑 | 数值格式化与类型名转换使用 `InvariantCulture` / `ToLowerInvariant` | 宿主语言不能改变协议数据与类型映射结果；显示名翻译与区域格式化是两件事 |
| 不翻译的内容 | 源码 XML 注释、协议报文、结构化日志、未标注本地化特性的第三方元数据 | 开发者文档与持久化数据应保持稳定；由 `LocalizedDescription` 生成的参数 Xml 注释会随语言翻译 |

## 2. 目录与文件

```
Locales\{ar,bn,cs,da,de,el,es,fa,fi,fr,he,hi,hu,id,it,ja,ko,ms,nb,nl,pl,pt,ro,ru,sv,th,tr,uk,vi,zh-Hans,zh-Hant}.yml
```

- 每个文件为逐行 `"英文原文": "译文"`，键必须与源码字符串**逐字一致**（含空格与标点）。
- 英文是源文与兜底，**不需要 `en.yml`**。
- 四个项目的 csproj 均通过 `<AdditionalFiles Include="..\Locales\*.yml" Link="Locales\%(Filename)%(Extension)" />` 挂载词表。
- 词表随程序集编译，模块初始化器自动 `Localization.Register`；类库默认不覆盖 Core 同名译文。

## 3. 编码约定

```csharp
// 自定义异常：IoTException 构造器内部翻译
throw new IoTException(IoTErrorCode.InvalidParameter, "Parameter cannot be null.");

// BCL 异常：显式翻译
throw new ArgumentException(L.T("Serial port name cannot be null."));

// 结果类型：Fail 方法内部翻译
return Task.FromResult(WriteResult.Fail(IoTErrorCode.InvalidParameter, "Node or parameter is invalid."));

// 日志：写英文模板与参数，Logger.Format 自动翻译（不要用字符串插值）
WriteLog("UDP broadcast to {0}:{1}, payload: {2}", broadcastAddress, port, body);

// 带实例前缀：前缀不参与翻译，先翻译再拼前缀
Log?.InfoPrefixed(LogPrefix, "UDP broadcast to {0}:{1}, payload: {2}", broadcastAddress, port, body);

// 运行时元数据：英文键，读取时翻译；兼容 GetDisplayName/GetDescription 与 Xml 注释生成
[LocalizedDisplayName("Serial driver")]
[LocalizedDescription("Serial port")]
```

**禁止字符串插值**（`$"..."`）：模板在进入日志/翻译前已被展开，无法再查表。运行时消息同样不得用字符串插值拼接模板。

**区域性敏感逻辑不得使用当前区域性**：协议解析、类型映射和小数精度计算固定使用不随宿主语言变化的实现，例如 `TypeHelper.GetIoTType` 的兜底名称用 `ToLowerInvariant()`，物模型步进精度用数值计算而不是 `Double.ToString().IndexOf('.')`。

**前缀不进入词表键**：`DriverBase` 与传输层的 `WriteLog` 统一走 `LogPrefix + InfoPrefixed`，先按 `LogCulture` 翻译并格式化消息，再拼接前缀。新增同类日志时不要写成 `$"[{Name}]{format}"`，也不要把 `[{0}]` 前缀放进格式串占位符。

## 4. 语言与开关

| 属性 | 说明 |
|---|---|
| `Localization.Culture` | 目标语言；默认跟随 `CultureInfo.CurrentUICulture`，应用可强制指定 |
| `Localization.LogCulture` | 日志语言；默认跟随 `Culture`，服务端建议固定为宿主语言，避免日志随请求漂移 |
| `Localization.Register(culture, table, overwrite)` | 运行时补充语言或下游覆盖译文 |

- `InvariantGlobalization=true` 下具名区域性不可用，源生成器跳过注册，运行时全部回退英文。
- 缺少译文的键不会抛异常，直接回退英文原文。
- `ServiceStatus` 的成员名是历史公开 API（如 `ServiceStatus.就绪`），为兼容性不重命名；界面显示应使用 `GetDescription()`，其返回的 `[LocalizedDescription]` 已随语言翻译。

## 5. 新增词条的流程

1. 源码中把中文消息改为英文模板；异常用 `L.T`，日志用模板 + 参数，运行时元数据改用 `LocalizedDisplayName`/`LocalizedDescription`。
2. 在 `Locales/` 下全部 31 个语言文件各加一行，键为英文原文；占位符集合必须一致。
3. 运行 `tools/check-locales.ps1`、`tools/check-english-exceptions.ps1`、`tools/check-log-messages.ps1` 与 `tools/check-runtime-messages.ps1` 确认通过。
4. 编译后词表在模块初始化时注册；缺译文的语言按英文回退。

## 6. 校验与门禁

```powershell
# 语言清单（locales.json）+ 键集合 + 占位符 + 孤儿键
pwsh -File tools/check-locales.ps1

# 代码字符串字面量不得包含中文（元数据特性除外）
pwsh -File tools/check-english-exceptions.ps1

# 日志模板必须登记到词表（避免运行时回退英文）
pwsh -File tools/check-log-messages.ps1

# 异常、结果、翻译入口、本地化元数据与日志模板统一校验（含多行调用与字符串插值）
pwsh -File tools/check-runtime-messages.ps1

# 盘点模式（不失败），用于新增文案后普查
pwsh -File tools/check-english-exceptions.ps1 -List
```

四条命令均在 `.github/workflows/test.yml` 的各平台单测任务中执行，任一失败即阻断。`tools/check-package-consumer.ps1 -Aot` 另行打包四个 NuGet 包并用临时消费者验证词表、驱动工厂、参数绑定与板卡串口工厂，同时执行 NativeAOT 发布与运行，由 `package smoke` 任务执行。

## 7. 测试

`XUnitTest/LocalizationTests.cs` 覆盖：

- 简体（`zh-CN` 归一化到 `zh-Hans`）与繁体翻译；
- 31 种语言 × 72 个词条逐个校验，确保没有回退英文的漏译；
- 程序集标题与描述以英文源文写入 csproj，词表提供目标语言译文，展示层 `Localization.Translate` 后生效；
- `TypeHelper.GetIoTTypes` 显示名随 `Localization.Culture` 切换，且不缓存旧语言；
- 串口/网络通用驱动的物模型 `Response data` 属性名随语言切换；
- 驱动显示名、枚举描述与参数 Xml 注释中的 `LocalizedDisplayName`/`LocalizedDescription` 随语言切换；
- 物模型步进精度在 `de-DE` 等以逗号作小数点的区域性下仍按正确位数取整；
- 物模型 JSON 往返在 `de-DE` 下仍使用点号小数点；
- IoT 类型兜底名称在 `tr-TR` 下仍使用不变大小写转换；
- 未提供语言回退英文；
- 驱动与传输层日志前缀，以及 `LogCulture` 对日志语言的覆盖；
- `IoTException`、`ReadResult`/`WriteResult`/`ControlResult` 的消息翻译。

`Localization.Culture` 是进程级全局状态，相关测试放入 `DisableParallelization` 集合串行执行。
